## The state machine

The heart of the service is a pure state machine — `ACTIVE`, `OVERDUE`, `CANCELED`… — with no dependency on NestJS or Prisma. It was written first, test-driven, and it decides whether an event changes state or not.

## Real idempotency

Every webhook carries an identifier. Before processing, the service records it inside a transaction; if it already exists, the event is ignored. Duplicates and redeliveries stop being a problem.

## Reconciliation

Even with idempotent webhooks, events can simply never arrive. Periodic reconciliation fetches subscriptions from Asaas, compares them to local state and publishes corrections as regular events — applications can't tell the difference.
